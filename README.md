# サプリ飲み合わせナビ（SuppleNavi）ブラウザ版

サプリ×サプリ、サプリ×食品、サプリ×お薬の「避けた方がいい組み合わせ」を **◎○△×** で判定するツール。
おすすめはせず、避けるべき組み合わせと目安量だけを示す設計。

## 公開URL

<https://shinm-pincom.github.io/supple-navi/>

## 起動

公開URLを開くか、`index.html` をダブルクリックするだけ。サーバー不要・ビルド不要・通信なし。

## 3つのタブ

| タブ | 中身 |
| --- | --- |
| 🔍 飲み合わせを調べる | 108件から2つ以上選ぶと総当たりで判定。リスト表示／一覧表（マトリクス）表示を切替 |
| 🎯 悩みから探す | 13カテゴリ・45の悩みから、関連が報告されている成分と目安量。★でエビデンスの強さを表示 |
| 📋 成分と目安量 | サプリ80成分の男女別目安量・上限量・タイミング・注意点を一覧 |

## 判定の4段階

| 記号 | 意味 |
| --- | --- |
| **×** | 避ける（併用しない、または医師の管理下でのみ） |
| **△** | 注意（多くは「時間をずらす」「量を控える」で対処できる） |
| **◎** | 相性がよい（吸収向上・相乗が報告されている） |
| **○** | 既知の重大な相互作用は報告されていない |

## 収録データ

- **108件**: サプリ成分 80／食品・飲料 17／お薬の系統 11
- **個別ペアルール 177件** + **作用機序タグルール 56件**
- **総判定可能ペア 5,778組** — 全ペアで判定が成立することを検証済み
- 悩み **45件** / 13カテゴリ

タグルールがあるため、個別に登録していない組み合わせでも作用機序が衝突すれば検出できる。
（例: 「抗血小板作用」×「抗凝固薬」→ 出血リスクとして自動で×）

## 検索の入力ゆれ対応

漢字・ひらがな・カタカナ・半角カナ・全角英数のどれで打っても同じものにたどり着く。

| 入力例 | ヒット |
| --- | --- |
| 鉄 / てつ / Fe | 鉄 |
| カフェイン / かふぇいん / ｶﾌｪｲﾝ | カフェイン |
| 血圧の薬 / けつあつのくすり | 降圧薬 |
| ワーファリン / わるふぁりん | ワルファリン |
| ＥＰＡ / omega / フィッシュオイル | EPA・DHA |

`engine.js` の `norm()` が半角カナ→全角、カタカナ→ひらがな、全角英数→半角、
長音・区切り記号の除去をまとめて行う。漢字名には `alias` にひらがな読みを持たせている。

## データの持ち方

```text
index.html         画面（3タブ）
css/style.css      見た目・印刷用CSS
js/data-items.js   成分・食品・薬マスター（用量・タイミング・出典・作用機序タグ）
js/data-rules.js   PAIRS（個別ペア）/ TAG_RULES（機序ベース）/ SOLO_ALERTS（単体注意）
js/data-goals.js   GOAL_CATS（悩みカテゴリ）/ GOALS（悩み→成分・目安量・生活習慣）
js/engine.js       判定ロジック（judgePair / judgeAll / soloAlerts / norm）
js/app.js          UI制御
verify.js          データ整合性チェック
verify-ui.js       UI配線チェック
verify-render.js   実描画テスト（jsdom）
```

データ追加はJSファイルに1行足すだけ。エンジンの変更は不要。

## 検証（データを追加・修正したら必ず実行する）

```bash
npm install      # 初回のみ（実描画テスト用の jsdom を入れる）
npm run verify   # 3本まとめて実行
```

個別に走らせる場合:

| コマンド | 内容 |
| --- | --- |
| `node verify.js` | **データ整合性 11項目。** ID重複、必須フィールド欠落、存在しない成分IDの参照、ペアの重複定義、実在しないタグを参照するルール、全5,778ペアの判定成立、主要18ケースの期待値テスト、悩み内の成分同士の衝突検出 |
| `node verify-ui.js` | **UI配線 9項目。** `$('#id')` の参照先の存在、data属性の読み書き整合、CSSクラスの定義漏れ、スクリプト読み込み順、印刷・モバイル対応、外部通信ゼロ、入力値のエスケープ、免責の常時表示 |
| `node verify-render.js` | **実描画 15項目。** jsdomで index.html を読み込み、クリック・入力・タブ切替を再現。納豆×ワルファリンが×になるか、検索の入力ゆれ19パターン、全45悩みの描画、108件を一括選択した最大負荷（108×108マトリクス・5,788組リスト）まで |

## 情報の根拠

- 日本人の食事摂取基準（2020年版）— 目安量・推奨量・耐容上限量
- 消費者庁 機能性表示食品の届出情報 — 実配合量
- 内閣府食品安全委員会（大豆イソフラボン、カフェイン）
- EFSA（緑茶カテキン、カフェイン）／FDA（オメガ3）
- 各成分の査読論文・メタ解析

各成分の `basis` フィールドに出典を記載している。

## 設計上の判断

1. **AI/APIを使わない** — サプリ・食品の相互作用は既知パターンが有限。辞書化すれば即応答・無料・オフライン動作・GitHub Pages直置きが可能。参考にした drug-checker はLLMで添付文書を解析する方式だが、処方薬が対象なら妥当、サプリなら辞書が有利。
2. **推奨をしない** — 「関連が報告されている成分」までを示し、必要かどうかの判断は医療者に委ねる。全画面に免責を常時表示。
3. **短文主義** — 判定は記号1文字＋一行、対処は「どうする:」の1行のみ。長い解説は置かない。
4. **サプリより先に効くことを併記** — 各悩みに `lifestyle` を持たせ、サプリが最善手でない場合はそう書く（例: 男性型脱毛はフィナステリドが最もエビデンスが強い）。
